Il est question de mettre sur pied un système d’invitations numériques avec QR code pour des mariages, galas ou séminaires d’entreprise ; l’appli ou le logiciel doit permettre d’avoir une base de données avec :

* Nom ;

* Prénom ;

* Téléphone ;

* Table assignée ;

* Statut d’émargement.

L’invité se présente avec son invitation contenant le QR code et, lorsqu’on le scanne, on accède au plan de table, ce qui permet de simplifier la gestion des invités. Il doit y avoir deux statuts :

✅ Invitation valide, on a le nº de table ou l’emplacement de l’invité 

❌ Invitation non valide ou déjà scannée à 19 h 03, par exemple, histoire d’éviter la fraude.

Modèle de données minimal (PostgreSQL / Supabase / SQLite)

Table guests :

id : UUID v4 (identifiant unique encodé dans le QR code)

first_name : String

last_name : String

phone : String

table_number : String (ex: "Table 4" ou "VIP A")

is_scanned : Boolean (default: false)

scanned_at : Timestamp (nullable)

Logique Anti-Fraude & Scan

Au moment du scan du QR Code à l'entrée, l'application envoie l'UUID à l'API. La requête en base de données doit être atomique pour éviter tout passage en double :

SQL
UPDATE guests 
SET is_scanned = true, scanned_at = NOW() 
WHERE id = 'UUID_DU_QR_CODE' AND is_scanned = false 
RETURNING *;
Si la requête renvoie la ligne mise à jour :
✅ Invitation Valide → Affichage dynamique : Nom, Prénom, Table assignée.

Si la requête ne renvoie rien (mais que l'UUID existe) :
❌ Invitation Déjà Scannée → Affichage dynamique : Refusé - Scanné à 19h03.

Si l'UUID n'existe pas :
❌ Code Invalide → Affichage dynamique : Invitation inconnue ou contrefaite.

Erreurs critiques à éviter

Mettre les données en clair dans le QR Code : Ne mets jamais le nom ou le numéro de table directement gravés dans le QR Code. Si le QR Code contient John_Doe_Table_5, n'importe qui peut fabriquer un faux QR Code avec un générateur en ligne. Encode uniquement l'UUID secret généré par ton système.

Créer une appli mobile native (iOS/Android) : Reste à 100 % sur du Web Responsive (PWA). Déployer sur les stores ou installer des APKs à la dernière minute fait perdre un temps précieux.

1. Côté Python : Backend & Génération (Exemple concis)
Script de vérification API (main.py)
Avec FastAPI et SQLite, le serveur tient en moins de 40 lignes de code :

Python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
import sqlite3, datetime

app = FastAPI()

# Autoriser les requêtes du smartphone/front
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)

def get_db():
    conn = sqlite3.connect("guests.db")
    conn.row_factory = sqlite3.Row
    return conn

@app.post("/check-in/{uuid}")
def check_in(uuid: str):
    conn = get_db()
    cursor = conn.cursor()
    
    # 1. Vérifier l'invité
    cursor.execute("SELECT * FROM guests WHERE id = ?", (uuid,))
    guest = cursor.fetchone()
    
    if not guest:
        return {"status": "INVALID", "message": "❌ Code non valide !"}
    
    # 2. Vérifier s'il est déjà scanné
    if guest["is_scanned"]:
        return {
            "status": "ALREADY_SCANNED",
            "message": f"❌ Déjà scanné à {guest['scanned_at']}",
            "name": f"{guest['first_name']} {guest['last_name']}"
        }
    
    # 3. Valider l'émargement
    now = datetime.datetime.now().strftime("%Hh%M")
    cursor.execute(
        "UPDATE guests SET is_scanned = 1, scanned_at = ? WHERE id = ?", 
        (now, uuid)
    )
    conn.commit()
    
    return {
        "status": "SUCCESS",
        "name": f"{guest['first_name']} {guest['last_name']}",
        "table": guest["table_number"],
        "message": "✅ Invitation valide !"
    }

⚠️ Point d'attention crucial pour le jour de l'événement
Les instances gratuites sur Replit se mettent en mise en veille (sleep) après quelques minutes d'inactivité.

Pour éviter que la première personne à l'entrée n'attende 20 secondes le réveil du serveur :

Solution simple : Gardez au moins un onglet ou le scanner ouvert sur un téléphone pendant la soirée.

Solution automatique : Configurez un ping gratuit toutes les 5 minutes via UptimeRobot vers votre URL Replit ([https://votre-projet.replit.app](https://votre-projet.replit.app)) pour garder le serveur actif en permanence pendant l'événement.

1. Phase de Préparation (L'Organisateur)

Importation des données : L'organisateur importe un fichier invites.csv contenant la liste des personnes (Nom, Prénom, Téléphone, Table).

Génération automatique : Le script Python génère un UUID unique par personne, enregistre les entrées en base SQLite et crée les cartes/images QR codes associées.

Distribution : L'organisateur distribue les QR codes aux invités (par WhatsApp, Email ou carte imprimée).

2. Phase d'Entrée - Le Parcours Fluidifié (L'Invité & L'Hôtesse)

Étape 1 (Présentation) : L'invité se présente à la porte et montre le QR code sur son téléphone (ou format papier).

Étape 2 (Capture) : L'hôtesse ouvre l'application web depuis son navigateur mobile ([https://gatsby.replit.app](https://gatsby.replit.app)) et pointe la caméra vers le code.

Étape 3 (Validation instantanée) :

Cas Succès (Écran Vert + Son de confirmation) : L'écran affiche en gros caractère :

✅ INVITATION VALIDE

Nom : Jean DUPONT

Emplacement : Table VIP 3

Action : L'hôtesse souhaite la bienvenue à l'invité et l'oriente directement vers sa table.

3. Phase de Contrôle - Gestion des Anomalies

Cas 1 : Tentative de réutilisation (Anti-fraude)

Écran Rouge + Bip d'erreur :

❌ ACCÈS REFUSÉ - DÉJÀ SCANNÉ

Invité : Jean DUPONT

Heure de passage : 19h03

Action : L'hôtesse refuse l'accès et signale la fraude potentielle.

Cas 2 : QR Code invalide ou inconnu

Écran Rouge : "❌ CODE INVALIDE OU INCONNU". L'invité est réorienté vers l'organisateur.

Cas 3 : Oubli / Téléphone déchargé (Fallback manuel)

L'hôtesse bascule sur un champ de recherche rapide (Nom / Téléphone), retrouve l'invité dans la base, vérifie son identité et valide l'émargement d'un tap.

4. Phase de Pilotage (L'Organisateur pendant la soirée)

Consulter le taux de remplissage en temps réel depuis son téléphone (ex: 145 / 200 invités arrivés - 72,5 %).
